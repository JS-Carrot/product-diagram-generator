# 结构抽取：把大白话拆成可核验的清单

这一步不画图，只产清单。清单错了，图画得再漂亮也是废的。

产出三个东西：**角色清单 / 主干步骤 / 异常分支**。

## 一、角色：谁在动手

角色 = **承担动作的主体**。不是部门名，也不是系统模块名。

判别口径只有一条：**它会不会自己发消息、自己改状态？** 会，就是角色；只是被提到的名词，不是。

| 是角色 | 不是角色 |
|---|---|
| 客户、运维、物流承运商、平台系统 | 「交易环节」「售后模块」 |
| 运营、财务、风控 | 「订单中心」（除非它真的独立发通知） |
| 第三方支付、WMS | 「其他」「相关方」 |

三条规矩：

1. 一个角色一条泳道。超过 6 个先问能否合并，别直接画成 8 条。
2. 系统角色照样算泳道（平台系统、WMS、告警引擎），因为它们的动作在图上要可见。
3. 「用户」这个词太泛，拆开：C 端客户、B 端管理员、内部运维，三者动作完全不同。

## 二、主干：正常路径长什么样

主干 = 从触发到结束的**正常路径**，每条写成 `谁 → 做什么 → 交给谁`。

抓三类动词：

- **发起类**：提交、申请、发起、上传
- **处理类**：审核、检测、复核、结算
- **通知类**：通知、回传、推送、同步

三条规矩：

1. 每个动作必须有主语。出现「然后就被拒绝了」这种，回问是谁拒绝的。
2. 相邻动作跨了角色，就是一个**交接点**，图上必须显式连边。
3. 主干只留正常路径。任何带「如果」「万一」「超时」的，全挪进异常清单。

## 三、异常：最容易被漏掉的一步

异常 = 让流程偏离正常路径的 **触发条件 + 处理方 + 结果**。

### 四问补漏

按这四问逐条扫，扫不出来说明素材还不够：

| 问 | 典型分支 | 常见漏项 |
|---|---|---|
| **等不到怎么办？** | 客户 7 天未寄回旧机 → 按日计逾期费；工单 4 小时未响应 → 升级业务负责人 | 只写了「等待」，没写等不到怎么办 |
| **被拒了怎么办？** | 入库检测不合格 → 发起维修工单；审核驳回 → 退回重提 | 写了驳回，没写驳回后回到哪一步 |
| **断了怎么办？** | 支付失败、接口超时、库存扣减失败 | 只画成功回调 |
| **撞车了怎么办？** | 重复提交、重复扣款、状态被并发修改 | 完全没考虑幂等与并发 |

### 每条异常必须写全三个字段

```text
触发条件：客户签收新机后 7 天仍未寄回旧机
处理方：平台系统
结果：按日计逾期费，流程仍停在「待寄回」，不终止
```

缺任何一个字段都要回问。**不要用「异常处理」四个字糊过去**——那等于没写。

## 四、素材不够时怎么问

按优先级从高到低，**一次只问 1–3 个**。一口气甩十个问题，用户会直接放弃：

1. 这个流程从哪件事开始触发？到哪一步算彻底结束？
2. 除正常走完之外，最常出岔子的是哪一步？
3. 有没有「等一个人/一个系统处理，但他不处理」的情况？超时后谁兜底？
4. 有没有驳回、退回、重来的环节？退回后回到哪一步？
5. 图里的系统是一套还是跨系统？跨系统的地方谁通知谁？
6. 有没有可能重复操作，或两个人同时改同一条数据？

问完仍缺的，交付时列成「待确认项」，**不自行补齐**。

## 五、清单模板

抽完整理成这个结构，作为画图的唯一依据：

```text
流程名：换机与旧机回收入库
触发：客户在控制台点击「申请换机」
结束：旧机检测合格并关闭工单 / 客户中途取消

角色：
  L1 客户
  L2 运维
  L3 物流承运商
  L4 平台系统

主干：
  1. 客户 → 提交换机申请 → 平台系统
  2. 平台系统 → 生成换机工单 → 运维
  3. 运维 → 锁定设备并出库 → 物流承运商
  4. 物流承运商 → 揽收并发货 → 客户
  5. 客户 → 签收新机并启用 → 平台系统
  6. 平台系统 → 计费切换至新机 → 客户
  7. 客户 → 寄回旧机 → 物流承运商
  8. 物流承运商 → 回运并签收 → 运维
  9. 运维 → 入库检测 → 运维
  10. 运维 → 确认数据已擦除 → 平台系统
  11. 平台系统 → 关闭工单 → 结束

异常：
  E1 触发：库存无可用设备
     处理方：运维
     结果：登记缺货与替代方案，客户接受替代则回到锁定出库，否则终止
  E2 触发：签收后 7 天未寄回旧机
     处理方：平台系统
     结果：按日计逾期费，流程停在待寄回，不终止
  E3 触发：入库检测不合格
     处理方：运维 → 平台系统
     结果：发起维修工单，4 小时未响应升级至业务负责人，处理完终止
```
