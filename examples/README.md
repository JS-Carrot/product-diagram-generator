# 示例集

两个案例，**同一条业务线的两种视角**——正好演示本技能的两条主出口：

```text
示例科技 · 车载数据迁移平台（设备租赁 + 车载数据回传）
├── device-swap-swimlane.*        流程视角：换机与旧机回收，谁在什么时候做什么
└── vehicle-data-migration-architecture/   结构视角：整个平台由哪几层组成
```

## 一、device-swap-swimlane（泳道图）

| 文件 | 说明 |
|---|---|
| `device-swap-swimlane.md` | 完整过程：结构清单 → Mermaid 源码 → 分层说明 |
| `device-swap-swimlane.drawio` | 4 泳道 · 20 节点 · 23 连边，原生 swimlane 容器 |
| `device-swap-swimlane-preview.png` | 渲染预览（交付前视觉校验用） |

覆盖的典型手法：

- 主干 11 步占 15 列，跨泳道交接点同列对齐
- 异常分支走 B 行（泳道高度 200），不与主干抢走位
- 三条异常三种归宿：回流主干（缺货替代）、原地滞留（逾期计费）、绕行再汇合（检测不合格）
- 「客户取消」这类终止型异常有独立终态节点，不留断头路

## 二、vehicle-data-migration-architecture（分层架构图）

| 文件 | 说明 |
|---|---|
| `architecture.md` | 完整过程：对需求草案的逐条修正 → 分层说明 → 已定稿决策 |
| `architecture.drawio` | 5 层带 · 30 模块 + 图例 + 「已定稿决策」带 |
| `preview.png` | 渲染预览 |

覆盖的典型手法：

- 层带横排、模块均分的坐标算法（见 references/drawio-rules.md 第三节）
- 核心业务域用暖色，是全图唯一抢眼的部分
- 决策带把「已定稿」结论印在图上，评审时不再重复讨论
- 分层说明只讲图上看不出的信息（规则归谁、哪些是别人家的系统）

## 三、怎么用这两个案例

- **抄结构**：画新图前先看对应案例的「结构清单」部分，照那个格式整理素材
- **抄排版**：`.drawio` 直接改文字就能变成你自己的图；坐标算法见 references
- **抄说明**：分层说明的四段结构照搬，内容换成你的业务

两个案例均通过 `check_mermaid.py` / `check_drawio.py` 校验（0 错误 0 警告），并经渲染预览逐块人工核对。
