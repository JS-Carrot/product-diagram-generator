PRODUCT DIAGRAM GENERATOR · 操作手册

产品流程图生成器
给产品经理的使用说明

把一句需求压成一张评审会上讲得透的图：跨角色泳道流程图、分层架构图，输出 Mermaid 源码、分层说明和可拖拽的 draw.io 矢量文件——结构经过校验，连线不会穿框压线。

1这个技能做什么

你用一段话描述业务流程或产品架构，它产出一组可以直接进评审、进文档、进 Wiki 的图：

图型典型用途输出
跨角色泳道流程图业务链路评审、跨团队对齐职责边界Mermaid 源码
+ 分层说明文档
+ draw.io 矢量文件（可拖拽修改）
主干流程图单条任务链、操作指引
状态机图订单 / 设备 / 工单的状态流转
时序图系统间调用、接口交互
分层架构图产品功能架构、技术方案评审

它和「画个图」的普通请求有三点不同：

  • 先问清再画：动笔前会确认角色清单、主干步骤、每条异常的出口，不会拿半截需求猜着画；
  • 异常必须闭合：每条异常分支都要有归宿（回流某一步，或明确终止），不允许出现「处理中」这种断头路；
  • 交付前机器校验：Mermaid 语法、draw.io 结构、连线穿框、连边交叉都跑自动检查，检查不过不算交付。

2安装（5 种方式）

技能本体是一个文件夹，放进 AI 助手扫描的技能目录即可。按你的情况选一种：

方式 A · 让 AI 帮你装（推荐，大多数人用这个）

把下面这段话发给你的 AI 助手：

帮我安装 GitHub 上的技能：https://github.com/JS-Carrot/product-diagram-generator
装到用户级技能目录，装完告诉我怎么用

方式 B · 命令行安装

仓库根目录就是技能本体，直接克隆到技能目录、名字对上即可，一条命令：

git clone https://github.com/JS-Carrot/product-diagram-generator.git
~/.workbuddy/skills/product-diagram-generator

方式 C · 项目级安装（团队共用）

把 product-diagram-generator 文件夹放进项目的 .workbuddy/skills/ 目录并提交进仓库， 团队成员拉下代码即人手一份，风格统一。

方式 D · ZIP 下载（公司网络挡 git 时）

仓库页点 Code → Download ZIP，解压后把 product-diagram-generator 文件夹整个拖进 ~/.workbuddy/skills/。仓库根就是技能根，拖进去这一层就对了。

方式 E · 免安装试用

打开仓库里的 SKILL.md，全文复制发给 AI：「按这份技能的规则帮我画图」——先试效果再决定装不装。

装完 30 秒自检

新开一个对话，说：「画个泳道图」。

  • 它先反问你角色清单、主干步骤、异常分支——装对了 ✓
  • 它直接开始编页面内容、或当成普通画图请求——没装对 ✗，回到方式 A 重装
技能清单在新对话开始时加载，刚装完必须新开一个对话才能生效。

3怎么提需求

好图来自好输入。提需求时把三要素说全：

画一张【业务场景】的跨角色泳道流程图。
角色：角色 A、角色 B、角色 C、平台系统
主干：步骤 1 → 步骤 2 → 步骤 3 → …（正常情况怎么走）
异常：①什么条件下出什么岔子，谁处理，结果如何
　　　②……
输出：Mermaid 源码 + 分层说明 + 可拖拽的 .drawio
✓ 够用的需求

画一张【设备换机与旧机回收】泳道图。角色：客户、运维、物流承运商、平台系统。 主干：申请 → 出库 → 签收 → 寄回 → 检测 → 擦除确认 → 关单。 异常：①库存缺货，客户可接受替代或取消；②签收后 7 天未寄回按日计逾期费；③检测不合格转维修工单，4 小时未响应升级业务负责人。

✗ 不够用的需求

画一个设备租赁的流程图。
缺角色、缺主干步骤、缺异常出口——AI 只能编。编出来的图评审会上第一个被挑战的就是「这条异常线去哪了」。

说不全也没关系：它会在 Stage 1 把缺的列出来逐项问你，你补一句它补一步，拼图式把需求凑齐。

4触发说法

方式示例
自然描述「把我们的退款流程梳理成一张图，拉通客服、仓库、财务三个角色」
带触发词说「画泳道图」「画流程图」「画状态机」「画时序图」「画架构图」「分层架构图」
直接点名「用 product-diagram-generator 画……」
要「架构图」时如果说「画个系统架构」，可能触发别的画图技能；点名 「产品功能架构图 / 分层架构图」更稳。

5七个阶段与三个卡点

全程自动推进，但三个卡点会停下来等你确认——该你说话的时候别划走：

Stage 1结构抽取角色/主干/异常清单
→
G1 卡点结构确认清单对不对，你说了算
→
Stage 2图型选型
→
Stage 3Mermaid 源码
→
G2 卡点异常闭合每条异常都有出口
→
Stage 4分层说明
→
Stage 5drawio 出口按需生成
→
Stage 6校验语法+结构+几何
→
G3 卡点校验通过全绿才交付
→
Stage 7交付
卡点它问什么你怎么答最省事
G1 结构确认角色清单、主干步骤、异常清单对不对？直接改清单：「把审批人换成财务」「补一条超时异常」
G2 异常闭合每条异常落到图上了吗？出口在哪？逐条说归宿：「这个回流到出库」「这个终止」
G3 校验通过校验报告 + 渲染预览给你看有不顺眼直接指：「这条线绕太远」「这两个框太近」

6交付物怎么用

Mermaid 源码

贴到任何支持 Mermaid 的地方直接渲染：GitHub / GitLab 的 Markdown、语雀、Notion、Typora、 mermaid.live。适合放进 PRD 和 Wiki，随文档版本走。

draw.io 矢量文件（.drawio）

  • draw.io 桌面版：双击直接打开，节点可拖拽精修；
  • 网页版：打开 app.diagrams.net 把文件拖进去；
  • Obsidian：装 draw.io Integration 插件后双击预览。

连线都写了显式锚点，draw.io 里打开的走线和预览一致，不会自动乱跑。 文件是标准 mxGraph XML，能提交进 Git 做版本管理和评审留痕。

校验脚本（可选，开发向）

python3 scripts/check_mermaid.py 图文件.md # Mermaid 语法与结构校验
python3 scripts/check_drawio.py 图文件.drawio --preview # 结构+连线几何校验，渲染 SVG 预览

校验含两条硬规则：连线不得穿过无关节点、两条边不得内部交叉—— 这两条不过关会直接报错，从机制上杜绝「箭头指到空处」和「连线竖穿节点」。

7迭代话术

图是改出来的。直接说改哪、怎么改：

想改什么可以直接说
加/删节点「在检测后面加一道复检」「把财务审批从主干拿掉」
改分支「缺货时客户也可能直接退款，补一条分支指向终止」
改布局「这两列挨太近」「这条线从上面绕」「这个节点挪到物流泳道」
换图型「这张改成状态机视角」「再出一张分层架构图」
改口径「角色名改成正式组织名」「异常线统一用红色虚线」

改完它会重新跑校验再交付，不会改一处坏一处。

8常见问题

装好了但说「画泳道图」没反应？

九成是没新开对话——技能清单在会话开始时加载。新开对话再试；仍不行就把 SKILL.md 全文贴给它（方式 E）先跑通。

它画的图和我脑中的流程不一样？

说明 Stage 1 的清单你没逐条确认。在 G1 卡点把三份清单（角色 / 主干 / 异常） 逐行核对，图只是清单的投影——清单对了图就对了。

异常分支被它「糊」过去怎么办？

它被要求每条异常必须有出口。如果你发现某条异常线没有归宿，直接在 G2 卡点点名： 「这条超时线现在没有出口，明确它回流到哪一步或终止」。

draw.io 打开后布局和预览不一致？

预览是近似渲染。所有连线已写显式锚点，正常情况完全一致；如个别边在 draw.io 里 自动路由偏了，把该边补上固定折点，或手动拖一下——矢量文件本来就是留给你精修的。

能直接出 Visio / PPT 吗？

draw.io 支持「文件 → 导出为 → VSDX / PNG / SVG / PDF」，从 .drawio 一步导出即可， 不需要本技能额外支持。

同一张图能给不同的人看不同版本吗？

用迭代话术生成「管理层版」（只留主干）和「执行版」（含全部异常），两份文件分开交付， 各自可维护。
